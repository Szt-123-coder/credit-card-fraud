# 信用卡欺诈交易预测

在极度不平衡的信用卡交易数据中识别欺诈交易，并说明在风控场景下模型该怎么评估和取舍。

## 业务问题
用交易的 V1–V28、金额和时段特征，预测这笔交易是否为欺诈（Class=1）。漏掉欺诈的代价（资金损失、赔付）大于误判正常交易的代价（用户被打扰），所以在**审核量可控**的前提下优先提高召回率。

## 数据
- 来源：公开的信用卡欺诈数据集（Kaggle「Credit Card Fraud Detection」，2013 年 9 月欧洲持卡人两天的交易），共 284,807 行。字段为 Time、V1–V28（PCA 匿名特征）、Amount、Class。
- 放置位置：下载后放到 `data/creditcardfraud.csv`。数据文件约 150MB，不包含在本仓库中。

## 数据口径
| 项目 | 口径 |
|---|---|
| 样本单位 | 一行是一笔交易，只做交易级预测 |
| 欺诈率 | 按笔数计算为主，按金额计算作为补充 |
| 去重 | 删除 1,081 行完全重复的数据，避免数据泄漏；剩 283,726 行，其中欺诈 473 笔 |
| 0 元交易 | 保留，作为试卡信号 |
| 时间 | 换算成相对小时 0–23，起点未知 |
| 切分 | 按时间先后，前 70% 训练、后 30% 测试；训练期最后 20% 作为验证集，用来调参和选阈值 |

## 结果（测试集，共 107 笔欺诈）
| 模型 | 抓到 | 漏掉 | 误报 | PR-AUC |
|---|---|---|---|---|
| 全猜正常 | 0 | 107 | 0 | – |
| 逻辑回归（未处理不平衡，阈值 0.5） | 55 | 52 | 22 | 0.70 |
| **逻辑回归（class_weight，阈值 0.985）** | **89** | **18** | **117** | **0.78** |
| 逻辑回归（SMOTE，同样的审核预算） | 88 | 19 | 131 | 0.78 |
| 决策树（深度 4，同样的审核预算） | 78 | 29 | 35 | 0.67 |

「全猜正常」的准确率高达 99.87%，但一笔欺诈都抓不到，所以本项目不用准确率评估模型。最终模型的阈值在验证集上选定，标准是被标记为可疑的交易不超过交易量的 0.2%。

## 主要发现
- 欺诈交易以小额为主：测试集里 56% 的欺诈金额不到 10 欧元，只拦截大额交易会漏掉大部分欺诈。
- 测试期的欺诈率（0.13%）低于训练期（0.18%），存在分布漂移。上线后需要监控审核量，并定期重新校准阈值。
- 局限：数据只有两天，欺诈样本少，特征经过匿名化，业务含义无法直接解读。
